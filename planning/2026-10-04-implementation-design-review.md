# 구현 설계 리뷰 (GPT)

대상: [S0~S3 구현 설계](2026-10-04-implementation-design.md). Codex CLI 0.160.0, gpt-6-astra를 읽기 전용 sandbox로 실행한 결과를 그대로 옮겼다. 반영 판단은 설계 문서 §13에 있다.

# 1차 리뷰 (r1, 2026-10-04, 추론 medium)

## 1. 총평

현재 설계는 구절 참조·정렬·승인 검증의 빈틈 때문에 잘못된 타이밍이나 오래된 음성을 정상 결과로 통과시킬 수 있어, 구현 전 수정이 필요합니다. `totalFrames` 산식과 경계 중심 크로스페이드 구간 산식은 타당하지만, 자막 표시 규칙과 엔진에 전달하는 시간 계약은 보완해야 합니다. HyperFrames의 실제 경계·seek 동작은 미확인입니다. 파일은 수정하지 않았으며 기존 작업 트리 상태를 유지했습니다.

## 2. 발견 사항

### G1 · P1 · 구절 ID 재사용으로 장면이 다른 구절에 연결됨

**위치** §4.4–4.5, D2  
**관측** 문장 안의 분할이 바뀌어도 `s01-p2` 같은 ID는 다른 내용에 재사용됩니다. 따라서 “분할 변경은 검증에서 걸린다”는 설명은 성립하지 않습니다.  
**영향** 모든 참조가 존재하고 순서도 정상인데 장면·항목이 잘못된 발화에 나타납니다.  
**수정안** `scenes.json`에 참조한 구절 목록의 내용·범위 해시를 기록하고 현재 분할 결과와 대조하십시오. 음성 시각 변경과 구절 의미 변경은 구분해야 합니다.  
**완료 기준** 문장 앞부분에 구절을 삽입해 기존 ID가 살아 있어도 이전 scenes가 거부됩니다.

### G2 · P1 · LCS 경계 매칭만으로 누락·반복 오류를 정상 처리함

**위치** §4.4, §7.2–7.3  
**관측** 구절 양끝만 매칭되면 내부 미매칭을 허용합니다. 반복 구절의 여러 대응 중 앞쪽을 선택하는 규칙은 결정론만 보장하며 정확성을 보장하지 않습니다. `review:auto`만 있어도 `status:ok`가 가능합니다.  
**영향** 발화 누락이나 반복 위치 오대응을 통과시켜, v2 §6의 미매칭·반복 오류 중단 및 미검수 구간 처리 원칙을 약화합니다.  
**수정안** 내부 누락과 복수 대응 가능성을 검수 대상으로 표시하고, 자동 정렬 성공과 사람 검수 완료를 분리하십시오.  
**완료 기준** 중간 어구 누락·반복어 삭제·문장 반복 fixture가 단조로운 시각을 가져도 검수 대기로 남습니다.

### G3 · P1 · 변경된 대본과 오래된 음성의 조합을 build가 차단하지 않음

**위치** §4.5, §4.7, §8  
**관측** 의미 검사는 ID·언어·정렬 상태를 확인하지만, 현재 합성 요청과 `voice.ttsKey`, 현재 발화·분할과 timings의 source 해시를 대조하도록 명시하지 않습니다.  
**영향** 대본 수정 후 `voice`를 생략하고 `build`하면 새 대본과 옛 음성이 한 run에 고정될 수 있습니다. 이후 jobs와 inputs 비교도 통과할 수 있습니다.  
**수정안** build에서 합성 요청 키, 실제 WAV 해시, 발화·분할 해시의 연결을 모두 검증하십시오.  
**완료 기준** 숫자·voice·적용 사전 변경 후 바로 build하면 오래된 음성 사용을 거부합니다.

### G4 · P1 · 승인과 재개가 전체 렌더 입력에 묶이지 않음

**위치** §4.7, §8  
**관측** final 조건은 draft 해시와 jobs 입력 일치입니다. 프로젝트 산출물·템플릿·폰트·설정 변경 검사는 없고, resume도 기록된 `inputHash` 비교보다 출력 해시 검사만 명시합니다. 완료된 draft/final 명령의 재호출 정책도 없습니다.  
**영향** 승인한 초안과 다른 내용으로 최종 렌더하거나 같은 run의 완성본을 덮어쓸 수 있습니다.  
**수정안** 승인에 렌더 의존성 전체의 해시를 묶고, final/resume에서 재검증하십시오. 완료 산출물 재호출은 동일 결과 반환 또는 거부로 고정하십시오.  
**완료 기준** 승인 후 프로젝트·폰트·설정 변경은 거부되고, final을 두 번 호출해도 기존 파일은 바뀌지 않습니다.

### G5 · P1 · S0 계약 완료 기준을 다른 시험으로 대체함

**위치** §4.5, §11 S0  
**관측** v2 §6·§10은 미등록 효과, 다른 효과의 params, 장면보다 긴 모션을 거부해야 S0 완료입니다. 설계는 이를 장면 유형·props·전환 시험으로 대체하고 요소 모션 계약을 S3로 미룹니다.  
**영향** 명시된 시험이 모두 통과해도 상위 계획의 S0 완료를 입증하지 못합니다.  
**수정안** 효과 계약과 최소 검증 fixture는 S0에 정의하고 실제 효과 설치는 S3에 유지하거나, 완료 기준 변경을 별도 결정으로 제안하십시오.  
**완료 기준** 상위 계획의 오류 사례마다 대응하는 시험 또는 승인된 단계 이동이 존재합니다.

### G6 · P2 · 자막의 ms 표시 의미가 프레임 변환에서 사라짐

**위치** §4.6, §5.4  
**관측** 자막을 frame으로 바꾸면서 시작·끝 반올림 규칙이 없습니다. v1은 프레임 시각이 `[startMs,endMs)` 안인지 판정합니다. 예컨대 `[120,1310)`은 frame 39에서도 보여야 하지만 끝을 round하면 39에서 사라집니다.  
**영향** 한 프레임 조기 표시·소멸과 구현별 결과 차이가 생깁니다.  
**수정안** gap 보정을 ms에서 먼저 적용하고 표시 판정을 유지하거나, 양 끝을 `ceil(ms×30/1000)`로 변환하십시오.  
**완료 기준** gap 249·250·251ms, 비정수 프레임 경계, 마지막 자막에서 ms 판정과 렌더 결과가 일치합니다.

### G7 · P2 · 크로스페이드의 자식 타임라인 계약이 불완전함

**위치** §4.6, §5.1, §5.4, §9  
**관측** timeline을 “모든 시각이 절대 frame”이라 하면서 `atFrame`은 상대값입니다. `$timing.durationFrames`가 명목 길이인지 확장된 clip 길이인지 불명확하고, 뒤로 연장된 구간의 처리도 없습니다. 마이크로초 내림은 clip 시작 비교만 설명합니다.  
**영향** 전환 중 요소가 일찍 움직이거나 끝 상태가 잘릴 수 있습니다. 자식 local seek와 루트 프레임 수 계산은 **미확인**입니다.  
**수정안** 명목 시작·clip 시작/끝·요소 상대 시각의 변환식을 명시하고 전환 전후 유지 상태를 정하십시오.  
**완료 기준** 홀수·짝수 전환, `frame % 3` 전 경우, 마지막 프레임을 실제 순차·역순 seek로 비교합니다.

### G8 · P2 · 정렬 캐시와 수동 수정 보존에 버전 경계가 없음

**위치** §7.4  
**관측** 캐시 키에는 자체 정규화·LCS 알고리즘 버전이 없습니다. jobs의 timings 보존 조건은 음성·분할 해시뿐이어서 whisper 모델·인자가 바뀌어도 자동 결과 전체를 유지합니다.  
**영향** 정렬기 수정이 적용되지 않거나 오래된 자동 결과가 새 검증을 우회합니다.  
**수정안** 자체 알고리즘 버전을 키에 포함하고, 수동 수정 보존과 자동 결과 재사용 조건을 분리하십시오.  
**완료 기준** 알고리즘·모델 변경 시 자동 결과는 갱신되고, 동일 구절의 수동 시각만 재검증 후 보존됩니다.

### G9 · P2 · timeout 이후 재호출과 비용 상한을 실제로 막지 못함

**위치** §6, §8  
**관측** timeout은 현재 실행만 멈춥니다. 다음 `voice` 호출에서는 성공 캐시가 없어 같은 요청을 다시 보낼 수 있습니다. 상한 검사도 실제 최대 출력 대신 45초 추정액을 사용하며, 재시도별 예약·불명 비용 처리 규칙이 없습니다.  
**영향** 사용량 확인 전 재호출하거나 승인된 월 상한을 넘길 수 있습니다.  
**수정안** 불명 요청 상태를 키별로 유지하고 확인 전 재호출을 차단하십시오. 유료 지원 시 각 시도에 보수적 비용 예약과 정산을 적용하십시오.  
**완료 기준** timeout 뒤 재실행의 호출 수가 0이며, 긴 음성·503 재시도도 잔여 예산을 초과하지 않습니다.

### G10 · P2 · 분할 불가능한 한국어·숫자 입력의 처리 규칙이 없음

**위치** §4.2–4.3, §7.1–7.2  
**관측** `1,200`, `3.14`의 구두점 예외와 공백 없는 긴 어절·제한보다 긴 사전 항목의 처리 규칙이 없습니다. 토큰 내부 시각 분배로 생기는 소수 ms 처리도 빠졌습니다.  
**영향** 숫자가 잘못 분할되거나 길이 제한·정수 ms 계약을 구현마다 다르게 처리합니다.  
**수정안** 숫자 내부 구두점은 보호하고, 분할 불가능한 초과 입력은 명시적으로 거부하십시오. 코드 포인트 범위와 정수 ms 변환 규칙도 고정하십시오.  
**완료 기준** 숫자·긴 한국어 어절·긴 치환·분해형 한글·이모지 fixture에서 범위 복원과 시각 검증이 일치합니다.

## 4. 뺄 수 있는 것 (simplicity)

- **§6 유료 호출 분기:** S2를 무료·수동 음성으로 제한한다면 유료 가격·상한 집행은 유료 사용 승인 시 구현할 수 있습니다. 호출 원장과 timeout 차단은 유지해야 합니다.
- **§11 위임:** Codex 대체 정렬기 구현은 우선 제외하고, 단일 구현을 독립적인 기준 시각 fixture로 검증하십시오.
- **§3 `scripts/lib/`:** 사용처가 생기기 전부터 모든 유틸리티 파일을 만들 필요는 없습니다. 실제 공통 코드만 추출하십시오.
- **§9 결정론 검사:** S1에서 seek 순서를 통제할 수 있는 방법 하나를 확정한 뒤, CLI 방식과 Playwright 방식을 모두 유지하지 마십시오.

# 2차 리뷰 (r3)

2026-10-05, 추론 high. 대상은 TTS를 ElevenLabs v4로 바꾼 r3이다.

## 1. 총평

[r3 설계](2026-10-04-implementation-design.md)는 승인·재개·시간 변환에 관한 1차 수정을 유지했지만, 수동 음성 경로와 정렬 검출 시험에는 구현 전에 고칠 결함이 있습니다. ElevenLabs 단일 합성·정렬 경로는 범위에 맞으며, 엔드포인트별 요청 계약과 크레딧 집계를 보완하면 됩니다. 실제 v4 호출·한국어 정렬 정확도·과금은 **미확인**이며, 파일은 수정하지 않았고 시작·종료 Git 상태는 같습니다.

## 2. 발견 사항

위치는 별도 표시가 없으면 대상 문서의 절 번호입니다.

### H1 · P1 · 수동 음성이 build 검증을 통과할 수 없음

**위치** §4.7, §6.5, §8, §11 S1  
**관측** 수동 음성 키는 ‘파일 해시+발화 문구’인데, `build`는 항상 현재 ElevenLabs 요청으로 계산한 TTS 키와 비교합니다. 또한 §6.5는 수동 음성에도 Forced Alignment를 요구하지만, S1은 정렬기 없이 수동 timings fixture를 사용한다고 정합니다.  
**영향** S1의 고정 음성 경로가 막히고, API를 사용할 수 없을 때 직접 만든 음성으로 제작을 끝내는 경로도 불완전합니다.  
**수정안** `provider: manual`에는 정규화된 WAV 해시·발화 해시를 검증하는 분기를 정의하십시오. S1에서는 검증된 timings fixture를 받아 정렬 호출 없이 진행하는 절차를 명시하십시오.  
**완료 기준** API 키 없이 수동 WAV+timings로 S1을 완성하고, 이후 WAV 또는 발화 문구를 바꾸면 기존 조합을 거부합니다.

### H2 · P1 · 정렬 검출 시험이 TTS 누락을 검증하지 않음

**위치** D6, §7.2–7.3, §11 S2  
**관측** 음성 A에서 정렬 텍스트만 줄인 A′는 주로 **음성에 추가 발화가 있는 상황**입니다. 텍스트에 없는 발화에는 평가할 단어 자체가 없어 반드시 `high-loss`가 나오지는 않습니다. `long-gap`은 구절 내부만 검사하여 구절 사이·음성 양끝의 삽입 발화나 태그 효과음을 놓치며, `repeat-risk`도 인접한 동일 구절만 탐지합니다. loss 값을 인위적으로 높인 fixture는 분기 구현만 검증합니다.  
**영향** 누락 검출이 검증되지 않은 채 G2 해결로 기록되거나, 정상적인 API 응답 때문에 ‘A′만 high-loss’ 완료 기준이 실패할 수 있습니다. 실제 검출률은 **미확인**입니다.  
**수정안** 누락된 음성+전체 대본, 전체 음성+축약 대본, 반복어 삭제, 구절 경계의 삽입 발화·SFX를 각각 시험하십시오. 특정 플래그 발생 대신 검수 대상으로 분류되는지를 평가하고, 검출하지 못하는 유형은 필수 청취 항목으로 남기십시오.  
**완료 기준** ko·en 실제 응답으로 검출·미검출 사례를 기록하고, 탐지 한계를 반영한 사람 검수 절차와 S2 합격 기준이 존재합니다.

### H3 · P1 · 4자리 해시가 변경된 구절의 기존 ID를 재사용함

**위치** D2, §4.4, §7.4  
**관측** UTF-8 문구의 SHA-256을 직접 계산하면 `항목 15입니다.`와 `항목 167입니다.`의 앞 4자리가 모두 `9ff9`입니다. 같은 문장 ID에서 교체하면 구절 ID가 그대로입니다. 동일 문구의 반복에만 붙이는 접미사는 이 충돌을 해결하지 않습니다.  
**영향** G1의 ‘문구 변경 시 이전 scenes 거부’ 보장이 깨지고, 같은 음성에서 수동 시각을 이관할 때도 잘못된 구절을 선택할 수 있습니다.  
**수정안** 구절 ID에 충분히 긴 해시를 사용하고, 중복 ID와 서로 다른 문구의 충돌을 거부하십시오. 수동 시각 이관에서도 전체 문구·범위를 대조하십시오.  
**완료 기준** 위 두 문구의 교체 fixture에서 이전 scenes가 거부되고, 서로 다른 구절 사이에 수동 시각이 이관되지 않습니다.

### H4 · P2 · Dialogue 대체 요청의 전체 계약이 빠져 있음

**위치** §4.2, §6.1–6.2  
**관측** Dialogue 예시는 `inputs`와 `settings`만 명시하여 모델·출력 형식·seed·언어·정규화 설정을 승계하는지 불명확합니다. 공식 API의 기본값은 모델 `eleven_v3`, 출력 `mp3_44100_128`입니다. ‘거부되면 전환’도 모델 미지원과 인증·크레딧 오류를 구분하지 않습니다. [Dialogue API](https://elevenlabs.io/docs/api-reference/text-to-dialogue/convert)  
**영향** 구현에 따라 다른 모델·형식으로 호출하거나, 실제 요청과 캐시 메타데이터가 달라질 수 있습니다.  
**수정안** 두 엔드포인트의 완전한 요청 예시와 `similarity`→`similarity_boost` 매핑을 정의하십시오. 전환은 S0의 모델·엔드포인트 미지원 확인에 한정하고, 실제 전송값으로 캐시 키를 만드십시오.  
**완료 기준** 요청 fixture로 v4·WAV·seed·언어·태그·정규화 설정을 검증하고, 401·402·429·timeout에서는 엔드포인트를 바꾸지 않습니다.

### H5 · P2 · 글자 상한과 크레딧 상한의 단위가 섞임

**위치** D8, §6.3–6.4, §7.2  
**관측** `monthlyCharCap`의 초기값은 크레딧인데 비교식은 글자 수이며, 뒤에서는 `creditsPerChar`를 곱합니다. 같은 원장에 있는 `kind: align`을 합계에서 제외하는지도 없습니다. 정렬은 시간 기준 과금인데 원장에는 과금 시간·크레딧 필드가 없고, 구독 차감 여부도 **미확인**입니다.  
**영향** 비율이 1이 아니면 상한 의미가 달라지고, 정렬 텍스트를 TTS처럼 합산하거나 정렬 비용을 빠뜨릴 수 있습니다.  
**수정안** 글자 상한이면 TTS 시도 글자만 합산하고, 크레딧 예산이면 필드명과 계산식을 크레딧으로 통일하십시오. 정렬의 차감 방식은 S0 필수 확인으로 두고 시간 기반 사용량을 별도 기록하십시오. 비용표는 정렬·태그·시험 호출 제외 추정임을 표시하십시오.  
**완료 기준** 비율 0.5·1·2, TTS+정렬 혼합 원장, 재시도·unknown·결제 주기 경계에서 기대 상한이 일치합니다.

### H6 · P2 · 유료 요청의 불명 상태 처리가 timeout에만 한정됨

**위치** §6.3, §7.2–7.4, §11 S2  
**관측** 재호출 차단은 120초 timeout에만 정의돼 있습니다. 전송 후 연결 단절·프로세스 종료의 복구 규칙과 요청 전 원장 기록 시점은 없습니다. 정렬 API에는 402·429·5xx·timeout 처리 규칙도 명시되지 않았습니다.  
**영향** 서버 처리 여부를 모르는 요청을 재실행하거나, 정렬 실패 시 합성까지 다시 수행하는 구현이 가능합니다. 5xx 요청의 실제 과금 여부는 **미확인**입니다.  
**수정안** 요청 전에 시도를 영속 기록하고 미완료 시도는 재시작 시 불명 상태로 다루십시오. 정렬에도 중단·재시도·상한 정책을 명시하되 성공한 음성은 유지하십시오.  
**완료 기준** 전송 직후 종료·연결 단절·정렬 timeout 뒤 무확인 재호출이 없고, 503 재시도마다 상한을 검사하며 TTS 성공 캐시를 보존합니다.

### H7 · P3 · r3 데이터와 시험 설명이 서로 맞지 않음

**위치** §4 공통 규칙, §4.2·4.4, §6.3, §11 S2  
**관측** 해시 설명은 값이 정수·문자열뿐이라고 하지만 settings와 loss는 소수입니다. 숫자 변경 시험은 원장 한 줄 증가를 기대하지만, 정상적인 새 TTS와 정렬 호출이면 두 시도가 기록됩니다.  
**영향** 정상 입력을 거부하거나 올바른 S2 실행을 실패로 판정할 수 있습니다.  
**수정안** 유한 소수의 직렬화 규칙을 명시하고, 원장 시험을 `kind`별 호출 수로 바꾸십시오.  
**완료 기준** 소수 settings·loss의 해시가 안정적이고, 숫자 변경 시 TTS 1회·정렬 1회를 확인합니다.

## 4. D6·D8 판단

**D6: 수정.** Forced Alignment 하나로 시작하는 방향에는 동의합니다. 다만 loss는 제공된 텍스트의 정렬 점수이며 독립적인 전사 검증을 대신하지 않습니다. [Forced Alignment API](https://elevenlabs.io/docs/api-reference/forced-alignment/create) S0에서 공백 생략 후에도 원래 코드 포인트 위치를 보존하는 대응표, 문장 오프셋, 구절 양끝과 단어 loss의 귀속을 확정해야 합니다. `apply_text_normalization: auto`의 숫자 변환은 공급자가 결정하므로, 숫자를 풀어 쓴 spoken과 원래 숫자를 둔 입력을 모두 시험해야 합니다. [TTS API](https://elevenlabs.io/docs/api-reference/text-to-speech/convert) 실패 시 whisper 경로는 별도 재설계 대상으로 두고, 당장은 수동 timings으로 끝낼 수 있어야 합니다.

**D8: 수정.** 구독 크레딧만 사용하고 PAYG를 충전하지 않는 운영 방침은 적절합니다. 유료 구독 중 생성한 음성을 사용한다는 원칙도 공식 상업 이용 안내와 맞습니다. [상업 이용 안내](https://elevenlabs.io/docs/help-center/legal/can-i-publish-the-content-i-generate-on-the-platform) 비용표의 12,600·39,600·79,200 계산은 가정 아래 맞지만, 실제 비율·정렬 비용을 확인하기 전 플랜 적합성은 추정입니다. H5–H6 보완이 필요합니다.

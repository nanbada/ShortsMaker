# Claude 기획 v2·모션 설계 리뷰

기준일: 2026-10-04 (Asia/Seoul). 대상: [기획 v2](2026-10-04-claude-code-render-plan-v2.md), [모션 카탈로그·프리셋](2026-10-04-motion-catalog-and-preset-tool.md), 기존 GPT 문서·v1 스키마·검증 코드. **문서 리뷰와 개선 제안이며, 구현·렌더 실험 결과가 아니다.** Claude 원문 두 파일은 보존했다.

## 1. 판단과 유지할 방향

**HyperFrames·Mac·Claude 대화형·고정 템플릿·언어별 음성 우선 제작 방향은 유지할 만하다. 다만 구현을 시작하기 전에 데이터 계약, 음성 캐시, 정렬 실패 처리, 모션 조립 방식을 구체화해야 한다.** 전체 아키텍처를 다시 조사하거나 두 엔진을 동시에 만들 필요는 없다.

유지할 선택은 다음과 같다.

- 매 편 AI는 대본·장면 데이터만 생성하고, 검증한 코드가 조립·렌더한다.
- 한국어·영어부터 시작하고 언어마다 음성 길이와 장면 배치를 다시 만든다.
- 첫 포맷은 정보·설명형이며 광고·캐릭터·3D는 순차적으로 확장한다.
- Mac에서 감독하에 첫 편을 만들고 VM·무인 운영은 실제 필요 뒤에 검토한다.
- 사람이 초안을 확인하고 게시를 결정한다. 대표 스냅샷 검토는 전체 영상 시청을 대체하지 않는다.

기존 GPT 자료에는 해시·재개·에셋·최종 출력 검사가 더 구체적으로 남아 있다. 그 원칙을 현재 단순한 제작 흐름에 옮기되 과거 VM 큐 전체를 다시 도입하지 않는 것이 적절하다.

## 2. 구현 전 해결할 항목

우선순위 P1은 구현 방향·결과 정확성에 직접 영향을 주는 항목, P2는 파일럿의 범위·운영 신뢰성을 보완할 항목이다. 아래는 발견 사항과 제안이며 변경 승인·실행 완료 기록이 아니다.

### R1 · P1 · 카탈로그 항목을 모두 같은 방식으로 조립할 수 없다

**위치:** 모션 §1 “결정론 문제도 이미 풀려 있다”, §3 “문자열 치환 수준”, §6 “항목별 라이선스 표기가 없다”.

**관측:** 공식 문서는 Block을 크기·길이가 정해진 독립 composition, Component를 다른 composition에 삽입하는 snippet으로 구분한다. `data-composition-src`는 composition 재사용 경로이며 모든 snippet이 그대로 독립 composition이 되는 근거는 아니다. 기여 문서는 선택 필드 `license`, `minCliVersion`, `registryDependencies`도 설명한다. 따라서 라이선스 필드 자체가 없다는 취지의 문구는 수정해야 한다. 개별 항목의 값·외부 에셋 권리는 여전히 확인 대상이다. [카탈로그 기여 문서](https://hyperframes.heygen.com/contributing/catalog), [변수 문서](https://hyperframes.heygen.com/concepts/variables)

**영향:** 설치한 효과가 단독 마운트되지 않거나 크기·재생 시간·ID가 충돌해 “ID만 바꾸기”가 실패할 수 있다. 등록 규칙의 존재는 M3·한글·우리 조합의 시험 통과 증거가 아니다. 공식 결정론 문서도 환경별 폰트·브라우저 차이를 설명한다. [결정론 문서](https://hyperframes.heygen.com/concepts/determinism)

**수정안:** registry에 항목 종류, 원본 revision/해시, wrapper 경로, 의존 파일, CLI 최소 버전, 라이선스 근거, 원본 크기·길이를 기록한다. Block은 composition adapter, Component는 검증한 wrapper, 셰이더 전환은 별도 연결 경로로 나눈다. 조립기가 텍스트와 JSON을 문맥에 맞게 직렬화하고 파일 경로를 검증하도록 한다. 단순 문자열 삽입으로 따옴표·줄바꿈이 HTML을 깨지 않게 한다.

**완료 기준:** Block·Component를 하나씩 같은 장면에서 2회 사용해 ID 충돌, 변수 전달, 9:16 배치, 로컬 의존 파일을 확인한다. 같은 환경에서 순차/역순/무작위 seek의 동일 프레임을 비교하고 경계 전후를 포함한다. 셰이더는 채택할 때 별도 시험한다.

### R2 · P1 · 언어 enum 변경만으로 v2 계약을 만들 수 없다

**위치:** v2 §6 마지막 문단, 모션 §3 `registry.json`·`scenes.json` 예시, 기존 `video-spec.schema.json`.

**관측:** 현재 계약은 `schemaVersion=1.0.0`, `language=ko-KR`, 장면 `text/image/browser/comparison/cta`, 문자열형 `motion`, `cut/crossfade` 전환이다. 모션 예시는 `keyword`, 객체형 `motion`, `transition.dur` 초 단위를 사용한다. registry에는 초 단위 길이만 있고 in/out 효과가 하나의 `params`를 공유한다. v2에는 완결된 새 스키마가 없다. 기존 Python 검증기는 원본 v1에 고정돼 있다.

**영향:** 언어만 확장하면 새 장면·모션이 계속 거부된다. 별도 검사 없이 통과시키면 프레임과 초, 전환 overlap, 효과별 파라미터 해석이 달라진다.

**수정안:** 새 `scenes.json`을 v2 편집 계약으로 삼을지 중간 입력으로 삼을지 먼저 결정한다. 권고는 v2 편집 계약 하나를 소유하고 HTML은 파생 출력으로만 만드는 것이다. v1 파일은 유지하고 새 스키마에 별도 버전을 부여한다. `ko/en/ja/zh` 입력 별칭과 `ko-KR/en-US/ja-JP/zh-CN` 저장값의 매핑도 한곳에서 관리한다. provider는 기존에 `google`이 있으므로 Gemini라는 이유만으로 중복 enum을 추가할 필요는 없다. 실제 모델 ID·API 경로·voice·adapter 버전은 별도 기록한다.

모션은 in/out 각각 `id`, `params`, `durationFrames`를 갖게 하고 `kind` 호환성을 검사하는 방향을 권고한다. 장면 경계 전환에는 overlap 여부와 길이 규칙을 명시한다. 화면 시간의 기준은 정수 frame, 음성·자막은 ms로 유지하고 초 변환은 엔진 adapter 경계에서만 한다. 효과 길이를 바꿀 때 타임라인을 늘릴지, 속도를 바꿀지, 최종 상태를 유지할지도 효과별 계약으로 정한다.

**완료 기준:** 완결된 한국어·영어 fixture가 새 검증기를 통과한다. 미등록 ID, 다른 효과의 params, 배경 효과를 text-in에 사용, 장면보다 긴 모션, 잘못된 overlap, 지원하지 않는 언어를 거부한다. 기존 v1 예시는 기존 검사에서 계속 통과하며 자동으로 v2라고 해석하지 않는다.

### R3 · P1 · “대본 수정 후 TTS 재호출 0”은 잘못된 인수 조건이다

**위치:** v2 §10 S1 완료 기준.

**관측:** 화면 문구 변경과 실제 발화 대본 변경이 구별되지 않는다. 그대로 구현하면 수정된 자막과 이전 음성이 다른 내용을 전달할 수 있다.

**수정안:** 인수 조건을 다음 두 경우로 분리한다.

| 변경 | 재사용·무효화 |
|---|---|
| 화면 문구·색·모션만 변경 | 발화 입력이 같으면 음성 재사용. 화면 문구와 음성의 의미 일치 및 영상 QA 재확인 |
| 발화 문구·발음 사전·voice·model·합성 설정 변경 | 해당 합성 단위의 음성, 정렬, 장면 타이밍, 영상, 기존 승인 무효화 |

캐시 키는 합성에 실제 전달한 텍스트·스타일·발음 변환·언어·provider/model/voice/settings·adapter 버전으로 만든다. 파일 해시를 확인한 성공 결과만 재사용한다. 한 편 전체를 합성했다면 문장 하나가 바뀌어도 전체 음성을 다시 만든다. 문단별 캐시는 그 방식이 청취 시험을 통과했을 때만 사용한다.

**완료 기준:** 제목 색만 바꾸면 TTS 호출 0회, 발화 숫자 하나를 바꾸면 새 음성과 정렬을 만들고 이전 승인을 거부한다. 음성 파일 손상 시 캐시 hit로 통과하지 않는다.

### R4 · P1 · 원 대본으로 글자를 바꿔도 타임스탬프는 자동으로 정확해지지 않는다

**위치:** v2 §1·§2·§5의 whisper.cpp → 원 대본 재정렬.

**관측:** whisper.cpp 공식 README는 단어 단위 타임스탬프를 실험적 기능으로 설명한다. 전사 글자를 원 대본으로 치환하는 것만으로 누락·반복·숫자 읽기·다국어 분절의 대응이 해결되지는 않는다. BudouX 줄바꿈도 음성 정렬과 별도 작업이다. [whisper.cpp](https://github.com/ggml-org/whisper.cpp)

**수정안:** `timings.json`에 원문 구간, 발화 구간, 시작/끝, `timingSource`, 미매칭 구간과 검수 상태를 보존한다. 발음용 텍스트와 화면 문구의 대응표를 유지하고 애매한 매칭을 임의 균등 분배하지 않는다. 미매칭·시각 역전·반복 대응 오류는 `needs_alignment_review`로 멈춘다. 첫 편은 phrase 자막으로 시작해 수동 구절 타이밍 보정을 허용하고, 단어 강조는 검증된 구간에만 사용한다. large-v3의 속도·메모리는 로컬 측정 전까지 보장하지 않는다.

**완료 기준:** 숫자·통화·약어·영한 혼용·반복어·문장 누락 사례를 포함한다. 언어별 대표 구간 10곳에서 수동 기준과 시작/끝 오차를 기록하고 각각 150ms 이내 목표를 확인한다. 미검수 구간이 있으면 통과로 표시하지 않는다. 이 표본 시험은 전 구간 정확성 보증이 아니다.

### R5 · P2 · 유료 대체와 F0 재합성의 중단 조건이 없다

**위치:** v2 §2 “무료 TTS 우선, 실패 시 유료”, “F0 중앙값 12%”, §7 비용.

**관측:** 무료 한도 오류, 음성 품질 오류, 모델 전환을 같은 실패로 처리하면 불필요한 재합성과 목소리 변경이 발생한다. F0 12%는 인용한 구현의 휴리스틱이며 이 채널의 언어·voice에서 검증한 품질 기준이 아니다.

**수정안:** 무료 quota 소진은 보류, 일시적 서비스 오류는 횟수 제한, 청구 여부 불명 timeout은 결과 확인 후 재개로 분리한다. 유료 경로나 다른 voice로의 전환은 이미 허용된 범위·잔여 예산이 있을 때만 수행하고 변경을 기록한다. F0는 최초에는 경고로만 쓰며 무성 구간·측정 불가를 실패로 재합성하지 않는다. 청취로 문제를 확인한 경우에만 제한된 재생성을 허용한다. 정렬 오류는 우선 타이밍을 고치고 음성 합성부터 반복하지 않는다.

**완료 기준:** quota/auth/timeout/F0 이상을 각각 주입해 보류·재시도·비용 예약 유지가 구분되는지 확인한다. 재시도까지 편당·월 상한에 포함한다. 수동 음성 입력으로 제작을 마칠 경로를 유지한다.

### R6 · P2 · 출력 덮어쓰기와 검수 승인 만료를 명시해야 한다

**위치:** v2 §6 `out/<id>/<lang>/` 구조와 §10 완료 기준.

**관측:** 고정 `final.mp4` 경로만 있고 재실행별 결과·검수 대상 식별 규칙이 없다. 기존 GPT 설계에는 run ID와 입력 해시에 연결된 검수 규칙이 있으나 v2에 명시적으로 이어지지 않았다.

**수정안:** `out/<id>/<lang>/<run-id>/`별 출력과 최소 상태 파일을 둔다. 대화형 P0에는 분산 큐가 필요 없다. 완료 파일을 원자적으로 기록하고 실제 파일 해시가 유효한 단계만 재사용한다. manifest에 입력·음성·에셋·템플릿·registry 해시, 도구 버전, fps/codec, 검사 결과, 사람이 검수한 출력 해시를 남긴다. 어느 입력이든 바뀌면 관련 결과와 승인 상태를 무효화한다.

최종 검사에는 실제 에셋·권리·해시, 폰트 로드, 문자 잘림, 장면·전환 경계, 음성 길이·잘림, 자막 범위, MP4 규격을 포함한다. 예시의 0 해시는 최종 출력에 허용하지 않는다. 내부 목표와 플랫폼 요구를 구분한다.

**완료 기준:** 렌더 중단 후 음성 호출 없이 재개, 이전 승인 영상 보존, 변경된 입력의 승인 재사용 거부, `ffprobe` 규격 검사, 초안 전체 청취·모바일 가독성 검토를 기록한다.

### R7 · P2 · 검증 상태와 버전 고정이 운영 선택을 실제로 막아야 한다

**위치:** 모션 §3 registry의 `langs`, §4 고정 `currentCommit`, v2 §10 준비 단계.

**관측:** 예시에 `en: verified`가 있지만 저장소에는 검증 영상이 없다. `langs`를 Claude가 읽는 설명으로만 두면 미검증 효과가 선택될 수 있다. catalog·CLI 설치 예시에도 정확한 버전이 없다. HEAD `647746e`만 전달하면 미추적 모션 문서·기존 자료가 전달되지 않는다.

**수정안:** 예시 검증값을 실제 시험 결과로 취급하지 않는다. 검증 상태는 언어·폰트·해상도·효과/adapter 버전과 증거 경로에 연결하고 생성기와 검사기가 함께 제한한다. 누락/미검증 언어는 거부한다. 설치 시 CLI·브라우저·FFmpeg·모델과 vendor 파일을 고정하고 인계 시 실제 HEAD와 미추적/변경 파일을 함께 기록한다.

**완료 기준:** 효과나 폰트 변경 시 기존 검증 상태를 다시 요구한다. 허용되지 않은 일본어 효과 선택을 렌더 전에 거부하고, 고정 파일만으로 네트워크 없는 재렌더를 확인한다.

## 3. 비용과 운영 수치 보완

v2 §5는 하루 편수를 언어별 최종 파일 합계로 정의하지만 §7은 월 90편×4언어=360개를 사용하고 §8은 언어당 하루 1편을 제안한다. **원본 주제 수와 언어별 출력 수를 구분해야 한다.** 월 90개 총출력과 90개 주제의 4개 언어 제작은 4배 차이다.

Gemini 3.8 Flash TTS 모델과 도입 단가는 공식 가격·음성 문서에서 재확인했다. Standard 기준 2026-12-31까지 입력 $0.50/100만 토큰, 출력 $9/100만 토큰이며 2027-01-01부터 각각 $1/$18이다. 오디오 25토큰/초도 공식 가격표에 있어 2차 출처에 의존할 필요가 없다. [공식 가격](https://ai.google.dev/gemini-api/docs/pricing), [음성 생성](https://ai.google.dev/gemini-api/docs/speech-generation)

45초 최종 파일을 기준으로 다시 계산하면 다음과 같다. 20% 재생성 여유는 실측이 아닌 계획 가정이다. 모두 **오디오 출력비만**이며 입력·이미지·검색·구독·세금·전기·사람 시간을 포함하지 않는다.

| 월 최종 파일 수 | 2026 출력비 | 20% 재생성 포함 | 2027 단가·20% 포함 |
|---|---:|---:|---:|
| 30 | $0.30 | $0.36 | $0.73 |
| 60 | $0.61 | $0.73 | $1.46 |
| 90 | $0.91 | $1.09 | $2.19 |
| 360 (4언어 확장 시나리오) | $3.65 | $4.37 | $8.75 |

산식: `fileCount × 45 × 25 × outputPricePerMillion / 1,000,000`. 입력비는 실제 대본·스타일 지시의 토큰을 별도 합산한다. 실제 음성이 45초를 넘거나 폐기한 음성이 많으면 총 합성 초로 정산한다. 무료 티어 적용량은 계정에서 확인하며 0원을 운영 보장값으로 삼지 않는다.

월 $10은 추가 지출의 목표/상한 제안이며 승인된 결제액이 아니다. 특히 360개·2027년·재생성 시나리오는 출력비만 $8.75이므로 이미지/추가 합성에 대한 여유가 작다. 초기 처리량은 전체 언어 합산으로 관리하고 확장 시 별도 예산을 계산하는 편이 명확하다.

## 4. 범위와 인수 순서 개선

현재 v2 S0는 반나절에 설치와 네 언어 40문장 청취, 모션 M0는 15개×2언어 갤러리를 요구한다. 동시에 S3는 일본어·중국어·광고·캐릭터로 확장한다. 기간은 보장값이 아니지만 첫 편보다 선행 준비가 커질 가능성이 있다.

아래는 기존 S0~S4를 대체 확정한 일정이 아니라 **범위를 줄이는 제안**이다.

| 순서 | 산출물 | 다음 단계 진입 조건 |
|---|---|---|
| A · 계약 정리 | R2의 스키마 경계·버전, R3의 캐시 규칙, 한국어 샘플 | 실제 지원 입력과 실패 조건이 명확함 |
| B · 첫 1편 | 권리 확인된 음성 입력, 한국어 45초·장면 3종·단순 전환 | 폰트·타이밍·seek·MP4 확인. 엔진 자체 실패 때만 Remotion 하루 비교 |
| C · 음성 연결 | Gemini TTS·구절 정렬·실패 처리 | R3~R6 통과, 숫자/고유명사 발음과 총 소요시간 기록 |
| D · 반복 제작 | 영어 추가, 서로 다른 주제 3편, `/short` 연결 | HTML 재작성 없이 완료, 사람 작업시간·재생성률·실패 비용 측정 |
| E · 최소 모션 도구 | 첫 편에 필요한 3~5개 효과, Block/Component 연결, ko/en 갤러리 | R1·R7 통과 후 원 계획의 15개로 확대 여부 결정 |
| F · 선택 확장 | ja/zh 또는 광고·캐릭터 중 필요한 한 축 | 품질·시간 근거를 확인한 뒤 다음 확장 |

첫 정보형 영상의 필수 요소가 아닌 F0 자동 판정·셰이더 전환·large-v3 최적화·VM·게시 API는 그 기능의 필요가 확인될 때 추가한다. 장면 5~6종과 다양한 모션 15개는 서로 다른 개발 범위다.

S3 완료 기준의 “언어별 2편 이상 게시”는 개발 산출물 완료와 외부 게시를 결합한다. “언어별 검수 가능한 파일 2편 + 검수 기록”으로 개발 완료를 판단하고, 실제 게시·성과 측정은 별도 운영 단계로 분리하는 것을 권고한다.

## 6. 이번 정리의 반영 범위

README를 현재 진입점으로 갱신하고 기존 GPT 문서에 v1/VM 이력 여부를 표시했다. 역할·인계 문서는 v2에 맞춰 갱신하되 이전 원문을 참고 구역에 보존했다. 모니터링 “생성 완료”는 확인되지 않은 과거 기록으로 구분했다.

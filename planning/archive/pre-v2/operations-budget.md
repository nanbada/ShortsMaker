# ShortsMaker 운영·토큰·비용 설계

> 상태: v2 이전 VM·야간 운영 설계와 비용 가정의 기록. 현재는 [기획 v2](../../2026-10-04-claude-code-render-plan-v2.md)의 Mac 대화형 운영을 따른다. 재시작·예산 통제 원칙은 참고 가능하지만 과거 TTS·CLI 비용표를 현재 견적으로 사용하지 않는다. v2 편수·TTS 비용 보완은 [리뷰 §3](../../2026-10-04-plan-review.md#3-비용과-운영-수치-보완)를 참고한다.

2026-10-04 기준. [종합 기획](2026-10-04-research-plan.md)의 실행 설계 부록. 모든 일정·상한은 제안이며 현재 예약 작업·유료 호출·모델 설치는 수행하지 않았다.

## 1. VM 우선 야간 운영

사용자는 Muse VM에 Claude/GPT CLI가 연결되어 있으며 구독 로그인이라고 확인했다. 기본 실행 위치는 Muse VM이고, 상세 선택·CLI 어댑터·Mac 대안은 [실행 설계](remote-execution.md)가 소유한다. VM의 자원·영속성·상시성·남은 구독 한도는 아직 미확인이다.

이전 조사에서 Mac은 M3 Pro·36GiB RAM·약 32GiB 여유 디스크로 관측됐다. 이는 대안 장비 정보이며 VM 사양으로 사용하지 않는다. 기본 경로에는 자체 LLM 설치 없이 Claude/GPT 서비스와 기존 CLI를 이용한다. 워커는 한 편씩 처리하고 렌더 동시성도 1부터 시험한다. 자체 음성·LLM은 별도 비용 이점이 확인될 때만 추가한다.

| KST 시간대 예시 | 작업 | 마감·실패 처리 |
|---|---|---|
| 전날 저녁 | 승인된 주제·자료와 기존 예비 콘텐츠 준비 | 매일 신선한 웹 검색이 필수가 되지 않게 설계 |
| 01:00~01:15 | 전원·디스크·예산·잠금·에셋 사전 점검 | 실패 시 작업 시작하지 않고 사유 기록 |
| 01:15~01:45 | 대본·음성·타이밍 생성 | 사용 가능한 기존 입력은 재사용 |
| 01:45~03:30 | 순차 미리보기·후보 렌더·자동 QA | 실패한 단계만 제한 재시도 |
| 03:30~04:00 | 결과 목록·비용·오류 보고서 작성 | 04:00 이후 신규 작업 금지; 실행 중 작업은 timeout 내 종료 |
| 아침 | 후보 시청·수정 또는 승인 | 승인된 해시의 파일만 게시용으로 표시 |

이 시간표는 처리시간 실측이 아닌 운영창 제안이다. VM 스케줄러는 실제 OS에 맞게 선택하고, 작업은 브라우저·SSH 종료 뒤에도 영속 서비스로 실행되는지 시험한다. 워커는 Asia/Seoul 날짜·운영창을 직접 검사하고 놓친 하루치를 다음 날 더하지 않는다. Mac 대안은 수면·전원·로그인 조건을 따로 시험한다. 예약 설정은 아직 설치하지 않았다.

## 2. 상태와 재시작 계약

권장 상태: `queued → sources_ready → script_ready → audio_ready → spec_valid → preview_ready → technical_qa_passed → rendered_candidate → needs_review → approved`.

예외 상태는 `held`(사유: `held_auth`, `held_quota` 등), `failed_retryable`, `failed_terminal`. Mac 대안에서만 `waiting_renderer`와 렌더 작업 임대를 추가한다. 자동화는 `needs_review`에서 완료하며 `approved`는 사람의 검수 기록이다. 게시 상태는 후속 게시 모듈에서 관리한다. 기술 QA 통과만으로 게시 승인을 만들지 않는다.

| 제어 | 제안 |
|---|---|
| 작업 식별 | 주제 ID+자료 버전+언어+템플릿 버전으로 `jobKey`; 재실행은 같은 작업을 찾아 이어감 |
| 중복 방지 | 단일 워커 잠금, 단계별 완료 파일, 원자적 상태 교체 |
| 입력 고정 | 대본·음성·에셋·spec·엔진·폰트·설정 해시 기록 |
| 재사용 조건 | 해당 단계의 모든 입력과 생성 도구 버전이 같고 결과 파일 해시가 유효할 때 |
| 실패 재개 | 처음 실패한 단계부터. 글꼴 오류로 재렌더할 때 TTS를 다시 호출하지 않음 |
| 제한 재시도 | 일반 외부 수집/API의 일시적 429/5xx는 최대 2회 추가. 구독 quota/auth는 재시도 대신 보류. CLI는 편당 시작 최대 3회 안에서 처리하고 대본 수정 최대 1회 |
| 애매한 timeout | TTS 요청 ID·응답 파일 확인. 서버 처리 여부 불명이면 `held`; 자동 반복 과금 금지 |
| 렌더 재시도 | 일시적 프로세스 실패만 최대 1회. 메모리 부족은 동시성 낮추고 1회, 같은 실패 반복 시 격리 |
| 단계 제한시간 | 초기 제안: 수집 5분, 텍스트 5분, TTS 10분, 렌더 30분; 실제 측정으로 조정 |
| 목소리 대체 | 다른 provider로 자동 전환하지 않음. 같은 언어라도 목소리·길이 변경을 기록하고 새 검수 필요 |
| 예비 콘텐츠 | 최신성이 중요하지 않은 검수된 주제 3~7개. 뉴스 실패를 오래된 사실로 몰래 대체하지 않음 |

웹 오류·권리 불명·출처 부족·문장 정렬 실패는 무제한 AI 수정 루프에 넣지 않는다. 해당 편을 보류해도 나머지 큐는 계속 처리한다. 원본·승인 영상은 덮어쓰지 않는다.

권장 결과 묶음: `candidate.mp4`, `captions.srt`, `thumbnail.jpg`, `script.md`, `claims.json`, `qa.json`, `manifest.json`, `cost.json`. 게시 제목·설명은 영어 초안으로 포함할 수 있지만 자동 전송하지 않는다.

manifest에는 요청 ID, 시도 횟수, 모델·목소리, 입력/출력 해시, 렌더 환경, 예상/실제 비용, 검사 결과, 사람 승인 해시를 기록한다. 키·토큰·쿠키는 로그와 산출물에 넣지 않는다.

## 3. 토큰 관리: 매일 코드를 새로 만들지 않기

기본 원칙은 고정된 템플릿·스키마·검사기를 재사용하고 AI에는 해당 편의 근거와 필요한 필드만 주는 것이다. 전체 프로젝트, 이전 대화, 모든 문서, 수십 장의 이미지를 매번 전달하지 않는다. 렌더 단계는 LLM 호출 0회를 목표로 한다.

### 편당 작업 예산 초안

| 작업 | 입력 토큰 목표 | 출력 토큰 목표 | 제어 |
|---|---:|---:|---|
| 근거 선택·대본·장면 의도 | 4,000 | 1,200 | 주제 1개, 근거 2~3개, 주장 ID 첨부 |
| 근거·문구 검토 | 2,000 | 400 | 문제 목록과 수정 필드만 출력 |
| 필요 시 제한 수정 | 2,000 | 400 | 최대 1회; 정상이면 호출 생략 |
| 보수적 계획 합계 | 8,000 | 2,000 | 1만 토큰/편 가정 |

위 수치는 실제 사용량이 아닌 비용 산정용 목표다. 워커는 단계별 input/output/캐시/추론 토큰을 공급자 사용량 필드로 수집한다. 숨은 추론이나 도구·이미지 입력 과금이 있으면 합산한다. 동작이 불안정한 프롬프트를 긴 추론으로 덮기보다 계약·예시·검사 오류를 개선한다.

직접 API를 쓰는 경우의 목표는 단일 요청 입력 6,000토큰, 편당 전체 과금 토큰 16,000이다. 하루 3편 48,000, 월 90편 1,440,000은 계획상 경보 기준이다. **구독 CLI에는 동일한 강제 토큰 상한을 보장할 수 없다.** 숨은 프롬프트·내부 호출·추론 사용량은 CLI 결과로 관측하고, 미제공 값은 `unknown`으로 기록한다.

구독 기본 경로의 강제 제어는 작성 1회+선택 검토 1회+수정 1회로 편당 CLI 시작 최대 3회, 단계 timeout 5분, 단일 동시 실행, 도구 범위 제한이다. 지원하는 turn 한도도 함께 사용하되 정확한 플래그는 설치된 제품에서 확인한다. 사용 한도가 소진되면 `held_quota`, 인증이 만료되면 `held_auth`로 보류한다. 유료 API·추가 크레딧 자동 전환은 하지 않는다. 일상 제작의 코드 수정은 허용하지 않는다.

캐시를 세 가지로 구분한다. 2·3번은 해당 API 경로를 선택한 경우의 기능이며 구독 CLI가 동일 제어·할인을 제공한다고 가정하지 않는다.

1. **로컬 결과 캐시:** URL 내용·대본·음성·장면 데이터·완성 파일. 같은 입력이면 외부 API를 호출하지 않으므로 가장 확실한 절감이다. 사실 데이터의 TTL은 별도로 관리한다.
2. **공급자 prompt cache:** 고정 prefix가 동일하고 모델의 최소 길이·TTL 조건을 만족할 때만 할인 가능하다. 예를 들어 Anthropic은 기본 5분, 추가 비용의 1시간 옵션을 설명한다. 하루 간격의 세 편에 항상 할인된다고 계산하지 않는다. 캐시를 맞추려고 불필요한 문서를 붙이지 않는다. [공식 문서](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)
3. **비동기 Batch API:** 사전 주제·대본 묶음에는 활용 가능하다. Anthropic은 50% 할인과 최대 24시간 처리·만료 조건을 설명하므로 당일 새벽 마감의 필수 경로에 두지 않는다. 전날 준비하는 상시 콘텐츠에만 후속 적용한다. [공식 문서](https://platform.claude.com/docs/en/build-with-claude/batch-processing)

편당 자료는 보통 2~3개 출처의 필요한 단락과 claim-source 표로 제한한다. 동일 주간 주제의 자료는 재사용하되 가격·버전·뉴스에는 확인 시각과 만료 조건을 둔다. AI가 만든 요약은 원문 URL과 연결되어야 하며 출처 없이 다음 작업의 사실로 재사용하지 않는다.

이미지 QA는 처음에는 장면별 대표 이미지와 전환 경계, 필요할 때만 실패 프레임을 본다. 다만 적은 이미지 검사가 전체 영상의 시간적 오류까지 보장하지는 않는다. 매번 영상 전체를 비전 모델에 보내는 비용 대신 자동 경계 검사와 사람의 최종 시청을 조합한다.

## 4. 비용 산정 전제

구독 로그인 기본안의 총비용은 아래 API 민감도 표와 다르다. Claude/GPT는 기존 구독 배분액·남은 사용 한도·허용한 초과 사용료로 관리한다. 기존 월 $1~3 추정은 직접 API 호출량을 가정한 비교 예시이며 Muse VM·구독 CLI 운영의 총비용 견적이 아니다.

30일 운영, 하루 1/2/3개면 월 30/60/90편이다. 기본 영어 45초, 편당 650문자와 입력 8,000·출력 2,000토큰을 가정한다. 대본 길이는 실제 말속도로 교체한다. TTS·LLM에는 계획상 20% 재생성 여유를 더한다. 통화는 USD이며 환율·세금은 별도다.

| 변수 | 30편 | 60편 | 90편 |
|---|---:|---:|---:|
| 최종 영상 분량 | 22.5분 | 45분 | 67.5분 |
| 기본 TTS 문자 | 19,500 | 39,000 | 58,500 |
| 20% 여유 포함 문자 | 23,400 | 46,800 | 70,200 |
| 20% 여유 포함 입력 토큰 | 288,000 | 576,000 | 864,000 |
| 20% 여유 포함 출력 토큰 | 72,000 | 144,000 | 216,000 |

문자 수와 토큰 수는 다른 단위다. 번역에 같은 비율을 적용하지 않으며 실제 글자·토큰을 다시 센다. 45초가 90초로 늘거나 모든 영상을 네 언어로 만들면 이 표를 그대로 사용할 수 없다.

계산식:

`LLM = (inputTokens × inputPricePerMillion + outputTokens × outputPricePerMillion) / 1,000,000`

`TTS = billableCharacters × characterRate` 또는 공급자의 정액제+초과 사용 공식

`월 총비용 = 구독 배분액 + 승인한 초과/API 사용료 + TTS + VM 배분액/추가 compute + 검색/정렬/이미지 + 엔진 + 저장/전송/미디어 + Mac 사용 시 전기 + 유지보수 노동`

`합격 1편당 비용 = 실패·재시도 포함 총비용 / 실제 게시 승인 편수`

### 모델 단가 민감도

아래 A/B는 **계산용 가상 단가 구간**이며 특정 모델의 현재 견적이나 선정 결과가 아니다. 실제 모델 선택 시 공식 단가와 계정 조건으로 교체한다. 캐시·Batch 할인은 적용하지 않았다.

| 구간 | 100만 입력/출력 토큰 단가 | 30편 | 60편 | 90편 |
|---|---|---:|---:|---:|
| A: 저비용 텍스트 모델 가정 | $1 / $5 | $0.65 | $1.30 | $1.94 |
| B: 더 비싼 모델 가정 | $3 / $15 | $1.94 | $3.89 | $5.83 |
| 완전 로컬 텍스트 | 외부 호출 $0 | 전기·설치·검수 별도 | 전기·설치·검수 별도 | 전기·설치·검수 별도 |

낮의 템플릿 개발·코드 수정은 별도 예산이다. 이 표는 운영 대본 호출만 계산한다. 예를 들어 B 단가에서 개발에 입력 100만·출력 20만 토큰을 쓰면 $6이며, 반복 수정에 따라 증가한다. 소비자용 AI 구독을 갖고 있다는 사실만으로 운영 API가 포함되거나 무제한 무인 호출이 가능하다고 가정하지 않는다. 사용 예정 상품의 계약·한도와 별도 API 청구를 확인한다.

### TTS 요금 비교

공식 페이지에서 2026-10-04 확인한 기본 단가로 계산했다. 무료 구간·첫 달 할인은 장기 비용표에서 제외한다. 실제 무료 구간이 적용되면 청구가 줄 수 있다.

| 방식 | 계산 단가 | 30편 | 60편 | 90편 |
|---|---|---:|---:|---:|
| Kokoro 로컬 | 외부 합성 호출 $0 | $0 | $0 | $0 |
| Google Neural2 | $16 / 100만 문자 | $0.37 | $0.75 | $1.12 |

## 5. 지출 통제

구독 CLI의 사용 한도와 종량 사용료를 분리한다. 실제 TTS/API/초과 사용은 사용자 예산 설정 후 활성화한다. 종량 비용의 제안 시작값은 편당 $0.25, 하루 $0.75, 월 $10이다. 이것은 소비 목표가 아니라 중단 상한이며 정액제·엔진 라이선스는 별도 고정비다. 더 비싼 작업은 보류한다.

호출 전에 남은 예산에서 최대 예상액을 예약하고 완료 후 실제 금액으로 정산한다. 오류나 timeout으로 실제 요금을 모르면 예약액을 해제하지 말고 대사 대상으로 남긴다. 공급자 청구 반영 지연 때문에 로컬 계산만으로 절대적 청구 상한을 보장할 수는 없으므로, 가능한 계정 한도와 알림도 함께 설정한다. 월 $10 도달 시 자동 충전·자동 업그레이드를 하지 않는다.

구독 작업은 `billingMode=subscription`으로 기록하고 표시된 토큰 환산액과 실제 추가 청구액을 분리한다. 잔여 한도가 조회되지 않으면 호출 횟수·중단 시각을 기록하고 다음 작업을 보수적으로 보류한다.

가격표에는 `provider`, `model`, `unit`, `currency`, `price`, `checkedAt`, `sourceUrl`을 보관한다. 새 모델·가격 변경·프로모션 종료 시 대조한다. 검색과 이미지·정렬 비용을 TTS 항목에 섞지 않는다. 일일 보고서에는 성공/보류/실패 수, 과금 토큰, 캐시 재사용, TTS 문자, 재시도, 실제·미확정 비용, 디스크 사용량을 담는다.

## 6. 저장 공간·전기·사람 시간

45초·8Mbps 영상의 비디오 스트림은 약 45MB다. 월 90편은 약 4.05GB이며 오디오·컨테이너·미리보기·원본 이미지·여러 버전은 추가된다. 1080×1920 RGBA 프레임 1,350장을 압축 없이 저장하면 약 11.2GB(10.4GiB)다. PNG 압축률은 내용에 따라 달라진다. VM에도 이 임시 용량을 예약해야 한다. Mac 대안의 이전 관측 여유 32GiB로 여러 작업의 전체 프레임을 동시에 보관하는 운영은 피한다.

제안: 선택한 렌더 호스트에서 운영 시작 전 여유 50GiB 이상 확보 또는 출력용 별도 저장소 사용. 워커의 최소 잔여 공간은 15GiB로 두되 예상 임시 파일 사용량을 추가로 예약한다. 32GiB라는 관측값만으로 운영 적합 판정을 내리지 않는다.

보존 정책 초안은 완료한 작업의 재생성 가능한 임시 프레임·미리보기 7일, 원본 대본·음성·권리·manifest·승인 영상은 장기 보관이다. 자동 정리는 명시적으로 허용된 임시 경로에만 적용하고 사용자의 원본·유일한 결과·백업을 지우지 않는다. 이 문서 작성 중 삭제·이동은 수행하지 않았다.

전기는 `평균 추가 소비전력(W) × 사용시간(h) / 1,000 × 전력 단가`로 계산한다. 예를 들어 60W·3시간·30일이면 5.4kWh다. 60W는 이 장비 측정값이 아니며 사용자의 실제 요금과 대기 전력을 반영해야 한다. 기기 구매·감가상각도 필요하면 별도 배분한다.

사람 검수 5분/편이면 월 30/60/90편에 2.5/5/7.5시간이 든다. 시급을 임의로 정하지 않고 실제 시간당 가치로 비용을 계산한다. 음성을 로컬로 바꿔 $1~3를 절감해도 검수가 길어지면 총비용은 늘 수 있다.

## 7. 운영 시험과 채택 기준

| 시험 | 합격 조건 |
|---|---|
| 같은 입력 재실행 | 새 유료 합성 0회, 이전 출력 덮어쓰기 0 |
| 자막만 수정 | 음성 캐시 재사용, 자막·영상·승인 해시만 갱신 |
| 언어 변경 | 해당 언어 음성·글꼴·길이 새 검증, 별도 jobKey |
| 네트워크 단절 | 완료된 로컬 단계 유지, 나머지 보류·재개 가능 |
| 강제 종료·재부팅 | 완료 파일 검증 후 재개, 잠금 복구, 중복 결제 요청 없음 |
| 구독 한도·인증 만료 | API 전환 없이 quota/auth 보류, 정상 복구 후 같은 작업 재개 |
| VM 세션 종료·재시작 | 영속 큐 유지, 중복 워커 없이 이어감 |
| 선택 Mac 결과 지연 | 오래된 임대 결과 거부, 유효 입력 해시의 결과 하나만 수락 |
| 수면·늦은 기상 | 정한 운영창 밖에서 갑자기 무거운 작업 시작하지 않음 |
| 디스크·예산 부족 | 외부 호출·렌더 시작 전에 중단 |
| TTS timeout | 미확정 청구 기록, 즉시 반복 호출하지 않음 |
| 음성 또는 에셋 변경 | 하위 단계 재생성, 기존 사람 승인 무효 |
| 3편 중 한 편 오류 | 해당 편만 격리, 나머지 후보 생성 완료 |

7일 하루 1편 파일럿의 결과를 기록한 뒤 하루 3편으로 확대한다. 편당 총 소요시간, peak memory, peak temp disk, 수동 수정분, 후보 합격률, 게시 승인률, 비용을 기록한다. 자동 기술 검사가 통과해도 실제 음성 청취·모바일 가독성·플랫폼 업로드는 따로 확인한다. 이 시험들은 이번 조사 단계에서 실행하지 않았다.
